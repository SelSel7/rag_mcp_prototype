# RAG MCP Prototype

This project implements a research-oriented prototype for evaluating different approaches to improving the reliability and reproducibility of responses generated by Large Language Models (LLMs).

The prototype compares three system configurations:

1. **Baseline LLM** – no retrieval, answers based only on internal model knowledge  
2. **Retrieval-Augmented Generation (RAG)** – always-on retrieval from a local document collection  
3. **MCP-based Retrieval** – selective retrieval using a structured tool interaction mechanism  

The goal is to analyse how retrieval and structured tool usage influence grounding, consistency, and efficiency.

## Requirments
- **Python 3.13**
- Ollama installed and running locally (llama3 model)

## Project Structure

- `baseline/` - baseline LLM without retrieval
- `rag/` - embedding, vectore stone and RAG pipeline
- `mcp/` - MCP-based retrieval pipeline and server
- `data/` - local document collection
- `results/` - experiment outputs (CSV + Excel)

## Setup

Create and activate a virtual environment.

### Windows PowerShell
```bash
python -m venv venv
venv\Scripts\activate
```

## Install dependencies:
```bash
pip install -r requirements.txt
```

## Data Preparation

Before running experiments, the document collection must be embedded:
```bash
py rag/embed_documents.py
```
This step:
- creates embeddings
- stores them in the vector database
- prepares the retrieval system for RAG and MCP

## Running the Prototype
### Single Test Run
```bash
py main.py
```
This runs one example query and prints outputs for all systems:
- Baselina
- RAG
- MCP

## Full Experiment Evaluation
```bash
py run_experiments.py
```

This executes multiple runs accross predifined questions and generates:
- Raw results
- Aggregated summaries
- Excel files for analysis

## Output
All results are stored in the results folder.
- experiment_results.xlsx => full raw data
- summary_overall.xlsx => system-level comparison
- summary_by_category.xlsx => grouped by question category
- summary_by_question.xlsx => per-question analysis

## Evaluation Metrics
The prototype uses quantitative metrics to compare system behavior:
- **Retrieval Rate** - how often external retrieval is used
- **Tool Call Rate** - frequency of MCP tool usage
- **Keyword Recall** - coverage of expected concepts
- **Citation Rate** - presence of grounded references
- **Response Time** - average latency
- **Consistency Similarity** - stability across repeated runs
- **Sensitive Leak Rate** - exposure of restricted information

## Key Idea
- **Baseline:** no grounding, fastest
- **RAG:** always grounding, but potentially inefficient
- **MCP:** selective retrieval, more controlled and modular
The prototype focuses on system design, not model training.

## Notes
This is a research prototype, not a production system.
The MCP implementation is simplified and focuses on structured tool interation.
The system is designed for controlled evaluation and reproducibility.
